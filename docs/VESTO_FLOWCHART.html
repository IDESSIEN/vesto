Invoice Lifecycle — State Machine

10 states · 14 transitions · All paths end in settled, defaulted, or disputed

State 01
Pending
Invoice submitted by seller. Awaiting admin review and risk scoring.
seller.submitInvoice()
State 02
Approved
Admin approved. Risk grade assigned. Registered onchain. Virtual account issued.
admin.approveInvoice()
State 03
Published
Visible in lender marketplace. Buyer acknowledgement required before funding.
admin.publishToMarket()
State 04
Funded
Lender USDC locked in VestoEscrow contract. Repayment deadline set. Seller receives repayment instructions.
lender.fundInvoice()
State 05
Payment Detected
BaaS webhook received. Full payment confirmed. 24-hour fraud buffer running.
webhook.paymentReceived()
State 06
Partial Shortfall
Buyer paid less than required. Proportional lender release done. 7-day cure window open.
webhook.partialPayment()
State 07
Settled
approvePayout() fired. Seller and lender can now claim USDC independently via pull model.
auto.executeSettlement()
State 08
USDC Repaid
Buyer paid directly onchain via buyerRepay(). Instant settlement. 0.5% fee discount applied.
buyer.buyerRepay()
State 09
Defaulted
repaymentDeadline passed. No settlement received. Lender can call claimRefund() for principal. Seller credit frozen.
timer.deadlineExpired()
State 10
Disputed
Admin blocked auto-settlement, or overdue escalation fired. DisputeResolution screen active. Admin resolves: refund lender or pay seller.
admin.blockPayout() / overdue

Hybrid Settlement — All 7 Lender Protection Layers

Each layer is independent — no single point of failure can lock lender capital

# Layer Mechanism Threat it neutralises Implemented in
L1 Buyer Acknowledgement Buyer countersigns invoice before any lender can fund. Cryptographic proof of debt. Fake invoice fraud by seller VestoEscrow.acknowledgeBuyer()
L2 Virtual Account Routing Each invoice gets a unique virtual bank account. Unambiguous payment matching. Payment sent to wrong account · Amount ambiguity invoice_virtual_accounts table · BaaS provider
L3 Automated Webhook Settlement BaaS fires webhook on payment. Edge Function validates and queues approvePayout() with 24h buffer. After buffer: unstoppable. Admin failure / absence / corruption payment-received · process-settlements Edge Functions
L4 Admin Override Window Admin can call blockPayout() within the 24h buffer. After expiry, no actor can halt settlement. Bank reversal fraud · Suspicious payment VestoEscrow.blockPayout() · Admin settlement queue UI
L5 Escrow Reversal Timer repaymentDeadline = invoice due date + 14 days. After deadline, lender calls claimRefund() for principal unconditionally. Buyer default · Permanent capital lock VestoEscrow.claimRefund() · LenderPortfolio countdown
L6 USDC Direct Repayment Buyer calls buyerRepay() on contract with USDC. Instant trustless settlement. 0.5% fee discount incentive. Bank settlement delay · Slow finality VestoEscrow.buyerRepay() · useBuyerRepay() hook
L7 Partial Payment Handling If buyer pays <100%: proportional lender capital released immediately. Remainder enters shortfall escrow with 7-day cure window. Partial non-payment ambiguity · Full lock on partial receipt invoice_shortfalls table · VestoEscrow._handlePartialPayment()
